# 存储模块实施状态

## 当前实施

生产 v0.1.31 已装配通用文件、存储、托管、贡献和准入。托管和贡献使用 `2026-11-20-v1` 同意说明。正式组件、提交和制品摘要见[发行记录](https://github.com/StuHelper/stuhelper/releases/tag/v0.1.31)。

| 组件 | 当前职责 |
| --- | --- |
| storage | 副本账本、内容共享与独立引用、容量预占、保护策略、执行器、运维查询与重试 |
| storage-bhpan | BHpan 登录、文件与目录、容量、分片传输、下载、回收站及分享协议 |
| media | 上传会话、不可变版本、审核读、业务引用、网关下载、本人免上传与共享内容清理 |
| storage-contribution | 同意、容量与期限、暂停、续期、退出、撤权、原实例重新启用及统计 |
| backend | 应用会话与服务身份装配、凭据保管和恢复，提供内置执行器及独立 `storage-worker` |
| Web 与 Admin | 本人托管和贡献、后台准入及运维。使用当前应用会话，按部署能力显示入口 |

三份完整副本是健康目标，两份独立合规副本通过 SHA-256 校验后允许首次业务引用。发布后只剩一份合规副本时继续读取并优先修复，零份时停止交付。

存储按保护条件和实例准入分配副本。普通贡献默认仅承载可公开分发的文件。管理员可按贡献者、存储准入角色或分组及实例配置级别。容灾范围包括账号和文件故障，整体供应商故障与跨供应商副本不在首期目标内。

通用存储服务于整个应用。资料审核、业务访问权、目录和下载包由 [resources](resources.md) 负责。放置、贡献与文件行为分别见[放置与恢复](../spec/storage-placement.md)、[存储贡献](../spec/storage-contribution.md)及[媒体引用](../spec/media.md)。

## BHpan 能力与证据

候选版本统一使用 BHpan 官方登录入口。两次人工登录均到达云盘回调。旧版本已用真实账号验证普通和分片上传、下载、文件校验与清理。候选版本的原实例重新授权和容量读取待负责人验收。[适配实施记录](https://github.com/StuHelper/stuhelper-storage-bhpan/blob/0a4ab1d46e38d793d82d917be8f4b266d20f89c9/docs/development/bhpan.md)

适配库提供显式 `RefreshSession` 入口。登录遇到交互验证时停止。同源相对跳转、拒绝不可信目标与会话续期已通过协议测试。秒传、归档下载、分享历史和共享目录遍历已通过夹具测试，真实账号验收待执行。

实际存储调度采用会话复用和获准托管凭据重登。独立客户端核对稳定账号及专用根后才切换材料。真实账号已验证会话失效后重登，并在另一套数据库及新进程恢复同一账号、根和副本。

原二十四小时观测因关机中断，闲置账号未做终点探测。随后独立恢复成功。持续无密码续期、实际到期机制及长期稳定性待验证，确认结果前不将 `RefreshSession` 作为当前存储自动恢复路径。

## 贡献容量与在线托管

develop 的 storage 会持久化容量观测及最后成功读取时间，读取失败保留原样本期限并安排补试。仍有效的旧样本可供放置判断，过期后停止新分配。本人贡献页面所需的读取状态与容量由贡献接口提供。[存储容量规格](https://github.com/StuHelper/stuhelper-storage/blob/a50bc27fb3cfeefad765809ed69a4d6388d52cee/docs/spec/storage.md)

本人容量接口区分尚未读取、读取失败和过期。申报上限为云盘剩余空间扣减实例安全余量及个人保留空间，最低为零，并受贡献策略约束。首次申报、重新启用及扩大申报范围均检查当前额度，执行时再复核。

原始容量只随本人视图返回。当前 develop 的 Backend 已装配新契约，Admin 已同步额度读取状态。生产 v0.1.31 使用已发行的组件组合。

Web 尚未接入本人容量和申报上限。首次读取额度尚未成功时，契约允许 `observed_at` 为空，Web 解析器只接受日期字符串，会把该响应视为不兼容。

新托管账号先登记为暂停、零贡献额度。本人的 `/me/storage?tab=accounts` 支持首次接入与凭据更新，未知结果查询原申请。管理后台只看脱敏记录和恢复原操作。更新凭据保留原实例、根、副本与贡献条件。

托管凭据按用途和期限加密保存。轮换保留原材料直至核验成功。撤权清除材料并阻止迟到核验重新激活。若账本已写入而候选凭据尚未激活，该实例停止传输，恢复原申请后再继续。

## 执行器部署

内置执行器、配置化 API 和独立 `storage-worker` 已实现。凭据库由单进程所有者独占，在线托管由该进程提供。按[执行器部署与资源预算](../design/storage-architecture.md#执行器部署与资源预算)分配并发、带宽和临时磁盘。

同进程同时提供 HTTP 和后台传输时，为前台预留至少一个传输名额。配置错误在装配时拒绝启动。独立 worker 仍受进程预算约束，多进程总预算与远程凭据服务在采用该部署方式时验收。

运维快照和 Prometheus 导出支持观察覆盖范围、缺副本及阻塞任务。集中监控和目标环境的吞吐、资源预算及告警验收待完成。
