# 框架实施状态

## 当前实现

platform 提供公共模块接口、依赖校验、能力降级、Fx 生命周期、HTTP 授权边界和可选远程连接。模块描述由其仓库的 `module.yaml` 生成，主仓库验证规格归属和公开能力一致性。

backend 负责正式应用装配。登录会话、公开昵称、学生认证、评价、审核、资料、媒体和存储已接入。campus-adapters 按学校配置启用。生产账务以仅账务模式运行，支付与交易范围见[后端交易配置](../guide/backend-commerce.md)。公共示例位于 platform 的 `examples/server`。

存储、媒体、存储贡献和资料由独立模块维护。副本、恢复与清理的实现及验证见[存储模块](storage-module.md)，资料上传、审核与下载见[资料模块](resources.md)。

Web 与 stuhelper-admin 提供八语言界面、错误恢复和 RTL 布局。国际化检查覆盖消息键、插值、复数与区域格式。两端主动切换语言时同步地址栏 `lang` 参数的行为仍待实现，见[国际化规格 I18N-09](../spec/internationalization.md#检查范围)。

stuhelper-tooling 维护共享检查器、GitHub Actions 工作流和 Lefthook 预设。根仓维护架构、Mani、跨仓检查和应用联调。ops 维护 SSO 官方制品与运行配置，backend 维护应用会话。

## 本人手机号

Web「账号与安全」已接入手机号查询、发码、绑定或换绑、解绑和近期认证。Session 0.9.0 的查询和换绑成功结果遵循[本人手机号脱敏规则](../spec/sso-compatibility.md#本人手机号)。生产短信投递和真实账号回调待验收。

PostgreSQL 与模拟 Casdoor 验收覆盖同期旧会话、查重、限频、验证码、解绑保护、写入读回和并发重复请求。本人接口已验证大陆裸号和带 `+86` 号码的显示、异常值的隐藏，以及同键重试返回相同掩码。

## 课程换号、目录与 QQ 登录

v4 索引按来源映射新旧课程号。搜索全量重建后，当前号、曾用号、中英文名和曾用名均命中同一门课程。旧课程链接解析到当前课程，课程详情展示英文名、曾用课程号和曾用名。Web 与后端同时切换。

目录增量事件和全量重建共用搜索文档转换逻辑。数据库回归覆盖增量与重建后的当前号、曾用号、中文名、英文名和曾用名查询。

Web 顶栏提供 QQ 登录入口。backend 把配置的提供方名称传给 Casdoor，普通登录和 QQ 登录共用 OIDC 回调。主站的 QQ 登录、互联绑定和解绑规则见[QQ 绑定规格](../spec/qq-binding.md)。

北航目录排除 office hours、博雅类和公共选修课程，体育与外语分类使用规范名称。体育项目由已确认的项目代码归纳，项目评价必须选择本人任课教师。训练队、运动队与裁判课分别展示，缺少项目代码的教学班保留为不可展示。

普通目录拒绝开课、教学班、任课关系和排课对象的读取与关联筛选。课程和教师公开摘要保留双方关联数量，省略教学班数量。管理端使用学校范围内的 catalog/admin 读取接口，继续使用完整摘要。

Web 接入通知内容名称、评价回复预览和学期排序。课程与教师列表支持滚动加载，学院分组分别预览和展开。资料关联学期与教师可选，校园认证页按状态、步骤和记录展示。“我的课程”继续关闭。

分组目录始终提供完整列表入口，包含未归属学院的课程。共享未读数通过状态修订防止旧请求覆盖全部已读或清空结果。相关回归覆盖多学院重复计数和异步响应顺序。

升级先执行目录迁移和运行权限配置，再准备策略与独立课程索引。完整导入后发布目录版本，保留旧索引。发布前备份业务库及配置。切换后保留新写入，继续限制教学班公开读取。

跨仓浏览器用例使用公开摘要和管理读取路径，覆盖隐藏教学班入口及旧链接跳转。源码检查、制品发行、生产目录数量、性能和真实账号验收分别记录。生产证据由私有 ops 维护。

## 搜索恢复

后端启动重建搜索时读取已发布的持久目录投影及其修订，沿用目录事件处理使用的快照。已发布投影在重启和重新投递后继续生效。

真实数据库检查覆盖目录事件先到、两次目录发布和搜索重建，以及截止学期变化后的索引与查询结果。完整应用启动通过公开维护命令准备学校目录，再等待搜索能力就绪。

## 邮件反馈

moderation 提供全站反馈收件箱，backend 接入 TLS IMAP IDLE、SMTP 与平台附件存储。全站联系地址统一为 `feedback@stuhelper.com`，群推送已取消。权限按当前会话执行，单校审核岗位不自动获得全站来信访问权。

来信按 UID 和 Message-ID 去重，正文转为纯文本，附件按类型及大小检查。列表只返回摘要，详情单独读取。回复结果未知时保留同一请求身份，管理员编辑使用独立版本，避免回复刷新覆盖另一位管理员的修改。

结案材料按 UTC 保存十二个自然月，覆盖闰日与数据库时区边界。真实 PostgreSQL 检查覆盖并发入库、授权与撤权、审计、附件引用、限频、总量、发送不确定结果和定期清理。

Admin 的 80 项反馈浏览器检查覆盖八语言桌面和手机、阿拉伯语 RTL、错误恢复及并发编辑。部署路径 /admin/ 的独立构建通过同一组检查。IMAP 与 SMTP 使用协议模拟服务验证，生产连通与真实账号体验由私有 ops 分别记录。

## 验证入口

| 范围 | 检查 |
| --- | --- |
| 工具库 | 检查器、暂存快照、日志与失败路径测试 |
| 架构 | 模块依赖、规格归属、工具链、文档与 Actions |
| platform | Go race、vet、构建、生成一致性、契约和导入边界 |
| backend | GOWORK=off 的正式依赖构建与检查 |
| storage-bhpan | 独立 Go 存储适配库、协议夹具、race、vet 与场景映射 |
| Web/Admin | 类型、lint、国际化、客户端用例与应用构建 |
| 公开组合 | 契约来源、兼容性与八语言桌面/移动浏览器测试 |
| ops | Compose、镜像引用、官方 SSO 候选与部署工具测试 |

各仓检查入口和跨仓验证方法见[检查指南](../guide/repository-checks.md)。正式 Go 构建使用 `GOWORK=off`。仓库依赖以 backend 的 `go.mod` 和 `go.sum` 为准，发行组合的版本及源码提交由根仓 `workspace.lock.json` 固定。
