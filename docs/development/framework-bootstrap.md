# 框架实施状态

## 当前实现

platform 提供公共模块接口、依赖校验、能力降级、Fx 生命周期、HTTP 授权边界和可选远程连接。模块描述由其仓库的 `module.yaml` 生成，主仓库验证规格归属和公开能力一致性。

私有 backend 的统一候选已装配登录会话、公开昵称、学生认证、课程目录、评价、审核、资料、文件与存储。公共示例仍位于 platform 的 examples/server。campus-adapters 按配置启用，账务尚未接入。真实存储验证沿用存储主题。

通用存储已有独立库，实现多账号准入、三副本、两份发布门槛、恢复与清理，见[实施状态](storage-module.md)。media 已实现文件上传、批准、引用与下载，backend 固定依赖联调通过。贡献管理和 resources 资料业务已有实现，见[资料实施](resources.md)。生产配置与真实账号验收由私有 ops 记录。

Web 与 stuhelper-admin 提供状态展示、错误恢复和八语言入口。Admin 另有存储运营页面，接口、权限和验收范围见[存储实施状态](storage-module.md)。国际化检查覆盖消息键、占位符、复数、数字、金额、日期、时区、相对时间和 RTL。

共享检查器、GitHub action、reusable workflow 与 Lefthook 预设已迁至 stuhelper-tooling。主仓库保留架构、Mani、工作区工具和应用联调。SSO 官方制品资料归 ops，后端身份实现归 backend。

## v0.1.26 课程换号与 QQ 登录组合

组合固定 backend v0.1.38、catalog v0.1.13、reviews v0.1.7、search v0.1.1 与 campus-adapters v0.1.21。Web v0.1.18、Admin v0.1.7 和 ops v0.1.23 的来源提交见 workspace.lock.json。

v4 索引按来源映射新旧课程号。搜索全量重建后，当前号、曾用号、中英文名和曾用名均命中同一门课程。旧课程链接解析到当前课程，课程详情展示英文名、曾用课程号和曾用名。Web 与后端同时切换。

目录增量事件和全量重建共用搜索文档转换逻辑。五种查询在两条路径下均已验证。此版本上线后如需修复，基于新版本发行下一版。旧槽位和 v3 索引作为参考保留。

Web 顶栏提供 QQ 登录入口。后端使用 Session 0.5.0 契约，将已配置的提供方名称传给 Casdoor。普通登录沿用同一会话与回调配置。

北航目录排除 office hours、博雅类和公共选修课程，体育与外语分类使用规范名称。体育项目由已确认的项目代码归纳，项目评价必须选择本人任课教师。训练队、运动队与裁判课分别展示，缺少项目代码的教学班保留为不可展示。

普通目录拒绝开课、教学班、任课关系和排课对象的读取与关联筛选。课程和教师公开摘要保留双方关联数量，省略教学班数量。管理端使用学校范围内的 catalog/admin 读取接口，继续使用完整摘要。

Web 接入通知内容名称、评价回复预览和学期排序。课程与教师列表支持滚动加载，学院分组分别预览和展开。资料关联学期与教师可选，校园认证页按状态、步骤和记录展示。“我的课程”继续关闭。

分组目录始终提供完整列表入口，包含未归属学院的课程。共享未读数通过状态修订防止旧请求覆盖全部已读或清空结果。相关回归覆盖多学院重复计数和异步响应顺序。

升级先执行目录迁移和运行权限配置，再准备策略与独立课程索引。完整导入后发布目录版本，保留旧索引。发布前备份业务库及配置。切换后保留新写入，继续限制教学班公开读取。

跨仓浏览器用例使用公开摘要和管理读取路径，覆盖隐藏教学班入口及旧链接跳转。源码检查、制品发行、生产目录数量、性能和真实账号验收分别记录。生产证据由私有 ops 维护。

## 搜索恢复

后端 v0.1.31 保留 v0.1.30 的搜索修复，复用已配置的目录快照。新投影事件进入搜索后，启动重建读取同一持久投影及其修订，避免以较旧的原始目录修订重建。

真实数据库检查覆盖目录事件先到、两次目录发布和搜索重建，以及截止学期变化后的索引与查询结果。完整应用启动通过公开维护命令准备学校目录，再等待搜索能力就绪。

当前锁文件用于 v0.1.26 的跨仓检查。源码检查、正式制品、生产同步、部署与真实账号验收分别记录，生产操作证据保存在私有 ops。

## 邮件反馈

moderation 提供全站反馈收件箱，backend 接入 TLS IMAP IDLE、SMTP 与平台附件存储。全站联系地址统一为 `feedback@stuhelper.com`，群推送已取消。权限按当前会话执行，单校审核岗位不自动获得全站来信访问权。

来信按 UID 和 Message-ID 去重，正文转为纯文本，附件按类型及大小检查。列表只返回摘要，详情单独读取。回复结果未知时保留同一请求身份，管理员编辑使用独立版本，避免回复刷新覆盖另一位管理员的修改。

结案材料按 UTC 保存十二个自然月，覆盖闰日与数据库时区边界。真实 PostgreSQL 检查覆盖并发入库、授权与撤权、审计、附件引用、限频、总量、发送不确定结果和定期清理。

Admin 的 80 项反馈浏览器检查覆盖八语言桌面和手机、阿拉伯语 RTL、错误恢复及并发编辑。部署路径 /admin/ 的独立构建通过同一组检查。IMAP 与 SMTP 使用协议模拟服务验证，生产连通与真实账号体验由私有 ops 分别记录。

## 统一业务组合验收

2026-10-29 的 business-acceptance 候选把认证与资料分支整合到同一 backend、Web 和管理端。会话绑定 issuer 与 subject，校园资格通过 verification 当前事实接口读取，署名昵称通过 profiles 公开接口读取。

| 流程 | 隔离验收结果 |
| --- | --- |
| 学生认证 | 手机拍照、提交材料、管理员批准、资格生效与删除申请批准通过 |
| 课程评价 | 当前学生资格、本人学期与教师、公开昵称、相同请求重放和冲突拒绝通过 |
| 导师评价 | 独立导师评论入口、匿名展示、手机号与学生资格检查通过 |
| 课程资料 | 上传真实文件字节、管理员审核、发布、三账号存储及内容一致下载通过 |
| 当前权限 | 无选课时不写评价，手机号解绑、学生资格删除、组织管理员撤权即时影响后续请求 |
| 故障与恢复 | 身份依赖故障后恢复、后端重启保留会话和资料、全部设备退出通过 |

浏览器直接调用正式 backend，数据库使用 PostgreSQL 18 和九个独立运行身份。OIDC/Casdoor 和 BHpan 边界使用隔离 TLS 协议服务，学校目录与本人选课使用合成数据通过管理接口导入。

业务流程脚本为 backend 的 scripts/business-acceptance.mjs，统一入口为 make check-business。结果包含 18 项流程检查、截图和源码提交。各仓必需检查另行执行；最终组合记录在 workspace.lock.json。

profiles 等全部已实现模块均已建立独立远端仓库、通过隔离数据库 CI 并发布正式版本 tag。正式 Go 构建使用 GOWORK=off，精确依赖由 backend/go.mod 与 workspace.lock.json 固定。

真实 SSO 发行版本、学校同步、邮件与实名渠道、真实 BHpan 账号按私有 ops 环境分别验收。备份恢复、到期清理与容量演练在上线前按规格核对。
