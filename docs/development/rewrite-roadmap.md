# StuHelper 开发路线

## 目标、范围与进度

工程基础、模块边界与业务规格见[框架工作记录](framework-bootstrap.md)和[检查指南](../guide/repository-checks.md)。认证、目录、评价、资料、个人主页、收藏与开放平台的实施状态由各主题维护。完整账务仍待交付。

## 当前交付安排

当前只推进 Web 和 stuhelper-admin，完成已确认的校园业务及模块协作。微信小程序、Android、iOS、HarmonyOS 与独立社交模块暂时搁置，重新启动时另定实施计划。后续端的参考设计继续保留。

| 阶段 | 成果 | 完成条件 |
| --- | --- | --- |
| 文档迁移 | 公共业务规格、私有模块文档、仓库边界和来源覆盖 | 已确认或明确延期的事项均有维护位置，全部文档检查通过 |
| 身份与工程基础 | 独立 SSO、模块接口、资格与权限、Web/Admin 基础 | 独立身份接入，模块依赖和停启行为通过验证 |
| Web/Admin 业务实现 | 评价、资料、目录课表、群管理、查询、通知、开放平台和存储贡献 | 对应规格的真实业务流程全部验证，账务与认证由私有模块对接 |
| 正式切换 | 数据迁移、兼容验证、恢复演练与生产部署 | 完整核对用户授权范围，并取得生产切换授权 |

## 身份数据与恢复

身份数据包含 SSO 账号、学生认证及 QQ 绑定。生产数据的导入、映射、核对与恢复按[SSO 兼容规格](../spec/sso-compatibility.md)执行，由获准的生产流程验收。

## 后续实现任务

- [ ] 在各模块仓库定义 API 与事件，形成固定版本的组合方案。
- [ ] 在私有 SSO、认证、学校适配及账务仓库实现相应能力。
- [ ] 实现 Web 与 stuhelper-admin，按已确认业务规格逐项验证。
- [x] 建立配置式模块启停、能力发现、依赖检查和可选远程连接降级框架。
- [ ] 按限定范围设计真实数据迁移与切换方案，并完成恢复演练。

## 待确认与验证限制

原生端与社交暂时搁置。课程评分维度、导师模板、匿名与署名、管理员处理和短时撤回规则由[评价规格](../spec/academic-content.md)维护。

已确认与延期的范围见[业务清单](business-decisions.md)。会员、奖励和价格由账务规格及运营配置管理。移动端签名、商店账号、HarmonyOS SDK 和 ArkTS 生成器在恢复对应端开发时验证。

会话与维护窗口由发布流程管理。容量、SLO、RPO/RTO 根据实际业务和基准测试确定。业务 API、真实登录和生产 Registry 性能仍未验收。三个应用镜像的本地构建与隔离组合已通过。Web/Admin 框架构建与联调结果由框架工作记录单独维护。
