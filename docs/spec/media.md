# 文件与媒体模块

## 数据与接口

media 承接通用文件入口，拥有上传会话、不可变版本、完整性摘要、内容类型、可用状态和业务引用。课程资料、用户资料及其他文件业务通过公开接口使用它，各自拥有业务描述、访问权和发布授权。

用途由服务端配置，固定所属业务、类型、大小与保护要求。用途接口按当前权限提供允许类型、单文件上限、会话时限和打包上限。供应商账号与密级由服务端管理。

上传支持整文件和按偏移分片续传。服务端确认实际类型、完整长度和 SHA-256 后才写入供应商。文件校验完成后仍须由所属业务独立批准。

文件使用稳定标识 ID，版本绑定上传者、名称、类型、长度和摘要。重试复用同一上传，参数改变被拒绝；新版本不替换旧版本的引用，跨上传者不能追加版本。单文件上限 1 GiB，实际大小与类型限制由用途进一步收紧。

上传状态依次为 created、uploading、verifying、awaiting_approval、approved、ready。cancelled、expired、rejected、deleting、deleted 停止交付；物理清理完成单独表达，不能将停止访问计为远端文件已删除。

## 隔离与发布

待审内容使用非公开分类，仅进入明确获准保管明文的平台实例。发布分类可以使用原分类，或在同一学校或组织范围内设为公开。共享引用转换时保留来源，待目标保护分组完成内容校验后再切换。旧版对象原地公开化仍要求来源实例同时获准承载新旧分类。

批准与存储就绪分别判断。首次引用发布至少需要两份独立健康副本，目标三份由存储异步补齐。业务依据当前审核及访问条件决定发布和交付。

审核读取复核当前审核权限，并在首次输出字节前写审计。审核驳回记录结构化原因、释放待发布引用并调度隔离副本清理。已批准版本和已有有效发布引用的版本按各自流程处理。

## 引用与下载

引用固定到版本、业务模块和业务对象，同一绑定不重复创建。引用模块须与上传用途一致，跨业务复用另建版本。pending、publishing 不允许读取，active 才开放，released 不可复活。

发布先持久化意图，再检查当前业务授权及副本门槛，最终确认引用。响应丢失后仍需获准请求重试；后台只恢复存储操作，不凭历史授权自动开放引用。业务授权器必须使用当前资格与业务状态。

文件通过引用网关交付。每次请求先检查停用状态、引用、分类和当前权限，实际返回文件时在完整内容校验后、首字节前再次检查。响应支持 HEAD、强 ETag、条件请求和 Range 续传。

成功响应使用 `Cache-Control: private, no-cache`，缓存复用前须重新验证。错误响应使用 `no-store`。文件名安全编码，默认以附件交付。允许的类型可在受限沙箱中内联显示。

释放引用立即停止该入口，其他有效引用继续使用同一版本。最后一个引用释放后进入持久清理。有有效引用时拒绝整文件删除。文件停用阻止新上传、引用和下载。迟到结果不得复活已取消版本。

当所属业务仍需源文件时，媒体保留源文件以备恢复，旧引用持续失效。重新发布使用新引用。业务解除保留后继续清理，保留查询失败时延后清理。

受限文件从首次上传开始使用独立版本密钥，适用于资料和反馈附件等用途。待审公开资料可在可信账号或私有 COS 暂存明文。涉及文件的业务在建会话前检查容量，发布时再核验实际副本。详见[存储规格](storage-placement.md)。

## 文件列表与打包

本人文件按创建时间倒序分页，可按用途和最新版本状态筛选。每项返回版本数量和最新版本摘要，并按全部版本的保护要求检查权限。

下载包只接受业务引用，最多 100 个文件、1 GiB，部署可收紧。逐文件输出前和结束前复核权限。ZIP 以编号目录避免同名覆盖，清单包含文件名、版本、长度、SHA-256 和估算包体积。打包复用有界暂存。

## 持久化与恢复

media 使用自己的迁移和受限数据库身份，不读取 storage 表。逻辑文件、版本、引用、任务、请求重放、审计与 outbox 均由本模块拥有；状态与事件在同一事务提交。传输不持有长期数据库事务。

任务有持久化租约、执行代次和明确重试上限。存储对象使用绑定服务身份与版本的稳定键，普通幂等窗口过期也不会重复创建。删除先停止交付，再释放本版本的存储引用。其他引用仍使用内容时保留副本；最后一个引用释放后，确认物理删除再报告清理完成。

上传会话、无业务引用版本和绑定待审引用的版本分别配置有效期，最长二十四小时。首次分配存储句柄时固定保留上限。过期上传与无有效保留理由的旧版本进入清理。文件、版本、引用和并发配额见[模块规格](https://github.com/StuHelper/stuhelper-media/blob/develop/docs/spec/media.md)。

分片续传使用有界私有暂存，下载与打包复用 storage 暂存。幂等重放保留 24 小时。outbox 投递详情完成后保留 90 天，审计保留 12 个月。物理删除确认后的墓碑在 30 天常规备份窗口后分批清理，受 `legal_hold` 保护的记录继续保留。

## 存储与运营

存储后端由独立适配器接入，当前使用 BHpan。通用存储管理实例、准入、容量和副本。backend 注入存储接口，文件接口使用通用类型。

用户贡献和激励分别作为扩展。贡献扩展协调同意、额度、期限和退出，奖励由获准统计和业务事件驱动；通用存储不依赖课程或奖励。关闭这些扩展后，平台实例和其他文件业务仍可服务。

当前方案只覆盖账号与文件层故障，不考虑 BHpan 整体服务故障。详细边界见[存储架构](../design/storage-architecture.md)、[放置规格](storage-placement.md)与[贡献规则](storage-contribution.md)。

backend 启用 media 时注入独立存储服务身份、当前授权与数据库配置，并启动恢复循环。运维接口按权限读取积压、重试阻塞任务并分批清理过期重放和已确认事件。就绪检查确认数据库和存储可用。

文件不可用、无权访问和交付方式不受支持分别返回明确结果。在线阅读器、加密容器和溯源的延期设计见[文件保护与交付能力](../design/file-protection-and-delivery.md)。

## 内容去重与免上传

新版本使用共享存储引用，独立保存上传者、文件名、审核与业务绑定。reuse_existing 开启本人免上传，服务检查已完成内容、当前读取权限、相同用途配置、内容类型、摘要、长度和保留期限，最多查询十个匹配候选。

reused 为 true 且状态为 verifying 时，客户端查询原会话，不重复发送内容。成功后进入 awaiting_approval，新版本仍独立审核。跨用户仅提交摘要必须实际上传，通过校验后才可共享物理副本。

同一保护分组仅保留一组副本。不同保护要求可能在转换期间各有一组副本，目标校验成功后释放来源引用。旧版存储对象不自动改写，历史内容批量归并另行处理。

| 场景 | 预期结果 |
| --- | --- |
| MEDIA-11 | 本人内容免上传，版本与审核独立；跨用户摘要不能取得内容，实际校验后可共享物理副本 |
| MEDIA-12 | 权限、停用和配置变化使来源不再可复用；响应丢失、重启及取消保留原标识和其他引用 |
