# 管理角色与配置操作

## 角色和范围

后台使用角色定义和作用范围授权。平台、学校、内容审核、资料、群和财务管理六种模板提供建议能力。服务端按授予的能力和对象范围逐次检查。仅可信平台管理员能创建角色定义，调整能力时使用新角色 ID。

平台管理员即 Casdoor 中标记为管理员的账号，自动拥有全部能力，包括敏感能力。其他管理员只处理获授权的学校、群和业务模块。

完整身份字段、认证材料、账务查询、导出和资金操作等敏感能力单独授予。授予与撤销须填写原因并提交当前授权修订号。普通管理员只可委托自己持有的能力和范围，平台级能力由平台管理员授予。服务端拒绝自我增权。

同一管理员的多项授权变更可在一次事务内提交。多管理员批量变更先预览，每批最多 50 人，执行时使用幂等键并逐项返回结果。

## 配置操作

页面展示配置当前值、作用范围、规则来源和最终生效结果。管理员修改前能看清影响对象。提交时发现其他人已经修改同一配置，应提示比较差异后重试，不静默覆盖。

各业务规定的参数、启停和动作资格由有配置权限的管理员维护。没有获准范围的管理员不能通过新增规则扩大自己的管理权。

## 存储管理入口

/storage 仅在服务端授权成功后展示脱敏实例、容量、副本与失败任务。状态读取、实例修改和任务重试分别授权；后台执行器身份不能获得人工操作权限。存储依赖不可用时仅关闭此页面的数据与操作，框架入口继续可用。

实例命令展示目标与动作，提交当前修订号。未知响应保留原幂等请求，重试不改请求内容；状态冲突后先刷新。任务仅对阻塞项提供重试入口，最终条件由服务端验证。未登录或无权限响应立即清空旧业务数据。

## 跨模块人工事件重试

跨模块 relay 的 outbox 事件连续退避满 24 小时后进入 `manual` 状态。backend 提供 `event-retry` 运维命令查看和重排此类事件。

Admin 的脱敏列表与按原事件 ID 幂等重试入口按 AO-07 验收，端到端装配待验证。列表只返回来源模块、主题、事件标识、脱敏错误码与时间。读取与重试分别授权，重试写入管理审计。

## 操作记录

platform 查询已装配的审计提供方，按时间、来源模块和记录 ID 降序合并。每页重新验证管理权限，游标绑定筛选、权限范围和提供方快照。提供方失败时返回已有结果及 `missing_modules`，恢复后从首页重新查询。

查看撤回消息不建立单独业务查看或审计记录，遵循群管理规格。其他管理处理结果和实际执行结果仍按相应业务记录，日志不复制认证材料或交易载荷。

## 验收场景

| 场景 | 预期结果 |
| --- | --- |
| AO-01：群管理员请求不在范围内的资料或财务操作 | 拒绝，不因角色模板而扩大范围 |
| AO-02：两名管理员同时修改同一配置 | 后提交者比较冲突后重新提交，不覆盖另一人的修改 |
| AO-03：管理员批量处理多个对象 | 先预览，再逐项显示实际成功或失败 |
| AO-04：查询角色希望执行退款或修改认证 | 另行检查操作权限，查询权不能代替操作权 |
| AO-05：平台管理员执行敏感操作 | 无需单独授予即可执行，操作仍记录审计 |
| AO-06：查询操作记录时某个模块不可用 | 返回其他模块记录，并列出缺少记录的模块 |
| AO-07：跨模块 outbox 事件进入人工队列后重试 | 仅向获授权管理员展示脱敏状态，按原事件 ID 与幂等键重投并记录审计，未知响应不重复产生业务写入 |

## 教师官网管理验收

后台教师官网刷新页面显示当前学校的任务、授课与官网标记人数，以及未匹配原因。管理员在人工处理入口查看待处理站点、目录教师和候选。查看、触发刷新与保存决定按各自权限和学校范围检查。操作规则见[目录维护](catalog-operations.md#目录投影与教师官网刷新)。

| 场景 | 预期结果 |
| --- | --- |
| TEACHER-SITES-01：读取刷新状态与匹配原因 | 显示四项教师人数、最新任务和分页原因清单。候选资料由人工处理接口提供 |
| TEACHER-SITES-02：触发增量刷新 | 请求携带幂等键，任务等待或执行时禁用重复操作，临时错误可以恢复，权限撤销后清除状态 |
| TEACHER-SITES-03：人工处理候选 | 分页展示站点摘要、目录教师、候选和原因，管理员可绑定、标记不对应或撤销决定，按服务端结果更新状态 |
