# 学生认证的公共对接说明

## 用户入口

个人中心分别展示学生资格、独立实名、手机号与 QQ 绑定状态。用户可以发起认证、查看结果，或申请撤销、删除已有学生认证。撤销与删除申请由管理员处理。

有效校园资格包括普通认证、已认证校友和未过期的临时新生。普通认证长期有效，只有限时凭证提示到期，群接纳范围及各业务动作条件使用对应配置。一个账号可以保留多段学习经历。

## 学校邮箱验证码出境

个人中心的学生认证继续通过 Resend 发送学校邮箱验证码。选择出站方式 `student_email_outbound_otp` 后，页面先展示《个人信息出境告知与同意书》的当前版本和全文入口。告知列明境外接收方、目的、处理方式、字段、保存地点与期限，以及撤回和行权途径。

页面提供「同意境外投递并发送验证码」和「返回选择其他方式」，初始没有预选。离开告知时停止发码，用户可继续使用学校已开放的其他认证方式。主站协议与隐私政策的同意凭证各自适用其文件。

页面使用专项同意状态返回的固定链接读取合格全文。`POST /api/v1/verification/applications/{id}/email` 的 `email_transfer_consent` 提交 `document_id`、`version`、`digest` 与 `accepted: true`。服务器核对本人申请和当前发布快照，先保存证据，再允许投递。[法律文件与版本](legal-documents.md)

同一申请用同一收件身份重发，可沿用尚未撤回的当前版本同意。新申请、更换收件身份或文件换版均须本人重新确认，并保存独立凭证。待发送或重试任务在调用 Resend 前重新检查同意。

`GET /api/v1/verification/email-transfer-consent` 返回当前文件引用、账号的有效同意状态和时间。用户在「个人中心 → 隐私与授权」以同一路径发起带 `Idempotency-Key` 的 `DELETE` 撤回。撤回可安全重试。主站协议待确认时，用户仍可在协议确认页查看和撤回有效的单独授权，也可通过专项告知所列隐私邮箱提交请求。

撤回拦截尚未开始的投递及后续重发。已送出的验证码沿用原有效期，已取得的学生资格继续按资格规则管理。恢复发送须本人重新主动同意。[数据保留与删除](data-retention.md)

| 发码结果 | 页面处理 |
| --- | --- |
| `403 email_transfer_consent_required` | 展示当前专项告知，等待本人主动确认 |
| `409 email_transfer_consent_changed` | 清除原确认，读取当前生效文件，展示新正文并等待重新确认 |
| `503 dependency_unavailable` 发布源不可用 | 提示学校邮箱出站验证码暂不可用，保留重试和返回其他认证方式的入口 |

| 场景 | 预期结果 |
| --- | --- |
| SV-EMAIL-TRANSFER-01 | 首次发码必须由申请人主动确认当前版本，服务器先留证再投递。缺少同意、快照变化或发布源不可用时告知相应失败。缺少凭证的历史任务停止投递，其他认证方式可用 |
| SV-EMAIL-TRANSFER-02 | 同一申请和收件身份重发沿用当前有效同意。撤回阻止未开始的投递与未完成的旧确认，恢复发送需重新确认，其他账号无法撤回本人的同意 |
| SV-EMAIL-TRANSFER-03 | 按北京时间自然年统计同校规范化学号，换账号、重发与重试不增加同一收件身份的计数。按未归并的收件身份数触发脱敏预警，只读命令返回汇总与统计口径 |

## 模块协作

业务模块按[动作资格配置](action-eligibility.md)检查服务提供的资格结论。服务不可用时，需要该结论的操作返回暂不可用，不将未知结果视为通过或失败认证。

用户已有内容与权益按相应业务规则保留。认证服务不直接修改评价、资料、账户或群成员数据，而是提供授权范围内的状态变化，由各业务处理。

## 教师认证与公开属性

认证模块对外提供有效教师资格、账号到教师档案的可信映射，以及获准公开的属性。属性包含来源、修订、有效期与公开授权，业务模块不读取认证材料。学生真实姓名、性别和学院，以及教师真实姓名、性别和单位，均按字段授权提供。

教师认证支持上传证明材料由管理员人工审核；当申请人验证通过学校教职工邮箱，且该邮箱与 catalog 唯一匹配的教师官网公开邮箱一致、无同名或归属冲突时，可完成快捷认领。同名歧义、官网无公开邮箱或档案已绑定时转入人工审核，不从昵称或普通登录推断教师身份。

一个账号可以绑定多份经人工确认属于本人的教师档案。目录合并后按规范 ID 处理。同一有效教师档案只能属于一个账号，归属冲突由管理员处理。

教师资格不替代任课关系。评课模块通过 catalog 查询教师是否曾教授目标课程，再按课程评价规格检查实名要求。学校同步通过共同的接入边界协作，课程和认证模块分别保存自己的业务数据。

## 私有规格

完整认证方法、材料处理、身份归属与核验规则维护在 [私有学生认证规格](https://github.com/StuHelper/stuhelper-verification/blob/develop/docs/spec/student-verification.md)。本页保留公共业务所需说明，不重复保存具体认证方案。

## 认证页体验

认证表单失败时，错误显示在对应提交操作附近，通过 aria-live 播报并接收焦点。学号、姓名和证件号等有效输入保留，密码沿用提交后清除规则。页面顶部横幅只报告页面数据加载失败。

实名和学校邮箱核验在接口中区分无记录与信息不符。无记录时，页面统一提示改用其他认证方式。信息不符时请用户核对所填信息，避免点名单一字段。学校账号提示区分凭据错误、锁定、停用和不可用，响应隐藏学校记录中的真实值。

实名、学校账号密码、发起邮箱核验及提交邮箱验证码共用响应时长和尝试次数保护。通过请求准入后默认至少 2.5 秒响应。触发额度、冷却或并发限制时返回 HTTP 429，并通过 `Retry-After` 与 `retry_after_seconds` 给出等待秒数。

学校资料只显示可识别的来源说明，空字段逐项标注未提供。认证时间取自当前所选凭证的 verified_at，没有对应凭证时隐藏时间。资料采集时间不用于表示认证时间。

| 场景 | 预期结果 |
| --- | --- |
| VERIFICATION-UX-01 | 认证方式、学习阶段和学生身份下拉框开关时位置与尺寸偏移为零，键盘选择和焦点恢复可用，其他页面保留默认滚动锁定 |
| VERIFICATION-UX-02 | 提交错误位于表单内且紧邻操作按钮，能够播报并聚焦。八语言按认证方式和失败类型提示，有效输入保留，页面加载失败使用顶部横幅 |
| VERIFICATION-UX-03 | 未知来源不显示，空字段逐项标注，不显示笼统的部分资料提示，认证时间绑定所选凭证而非同校其他凭证或资料采集时间 |

上述场景覆盖八种语言的桌面与移动视口，阿拉伯语使用 RTL。检查方法和翻译规则遵循[国际化规格](internationalization.md)。
