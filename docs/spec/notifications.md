# 通知中心

## 范围

通知中心通过站内消息向用户展示互动、安全、账号和业务处理结果。来源模块写入待发送事件，backend 按模块协议投递，notifications 保存本人通知和已读状态。

## 站内通知与操作

| 来源 | 通知内容 |
| --- | --- |
| 内容互动 | 本人内容收到回复、点赞等互动 |
| 内容管理 | 内容处理结果、资料下架申请处理结果 |
| 举报 | 本人举报的处理结果 |
| 认证 | 学生认证或实名核验结果，学生认证撤销、删除申请处理结果 |
| 系统 | 与用户有关的系统通知 |

Web 消息中心按互动、审核、认证和系统消息组织列表。用户可查看未读数、将单条或全部通知标记已读，并打开可访问的关联内容、申请或结果。失效或暂不可用的目标显示当前状态。

服务端接口还支持按分箱、通知类型和未读状态分页，按分箱或类型标记已读，以及删除本人的单条通知。删除保留投递去重记录，重复消费原事件不会重新生成已删除的通知。

业务处理、安全和账号通知不受互动偏好影响。服务端分别提供评论回复与点赞开关，默认开启。Web 当前提供统一互动开关。聚合通知按最近一次发生时间排序，此时间随窗口内新互动更新。

保留期限和聚合窗口由部署配置。QQ 群内提醒由[群服务](qq-group-services.md)处理。

导航铃铛、首页和消息中心共享未读数。并发读取复用同一请求，一分钟内复用已知结果。标记已读或全部已读后的状态优先于较早请求，读取失败保留已知值，未知值不显示数字。

通知列表通过 include_content_names=true 取得当前内容名称。可访问内容使用名称，失效或无权访问时显示不可用，依赖故障显示名称暂不可用。旧服务未返回增强字段时保留编号，内容名称不写入通知持久数据。

## 验收场景

| 场景 | 预期结果 |
| --- | --- |
| NT-01：用户收到回复通知 | 列表展示通知，点击进入对应内容 |
| NT-02：用户标记一条或全部已读 | 对应未读状态和未读数更新 |
| NT-03：申请已被管理员处理 | 用户能看到结果并进入相关申请 |
| NT-04：通知关联内容已下架 | 告知内容当前不可用，不误报加载成功但无内容 |
| NT-05：未登录或偏好输入无效 | 拒绝请求，不修改通知偏好 |
| NT-06：通知写入失败或达到保留边界 | 事务失败回滚，按保留期清理，聚合区分目标、参数与接收人 |
| NT-07：通知标题与参数 | 使用服务端封闭标题目录，拒绝无效标题与参数，互动计数来自聚合结果 |
| NT-08：重复事件与旧修订 | inbox 去重并返回原结果，旧修订不覆盖新状态，失败回滚聚合与修订 |
| NT-09：一个事件包含多个收件人 | 去重并逐人应用偏好，全部通知、inbox 与修订同事务写入，失败全部回滚 |
| NOTIFY-BELL-01：共享未读数与并发更新 | 页面共用当前数值，单条或全部标记已读后保持更新结果，读取失败保留已知值 |
| NOTIFY-NAME-01：读取通知内容名称 | 使用当前可访问名称，隐藏或不可用时显示对应状态，旧响应保留编号 |
| NT-10：已认证教师订阅所授课程新评价汇总 | 开启后按日聚合推送课程新增公开评价数，关闭或待审撤回内容不发送，载荷不含匿名作者身份 |

## 配置与后续事项

教师主动订阅的授课反馈汇总保留为待实现规格。默认按日汇总，仅包含所授课程名称和新增公开评价数，排除匿名作者身份及未公开内容。

邮件、QQ 和客户端推送的接入待验证。外部渠道启用后按用户偏好发送。免打扰延后外部推送，站内通知仍可查看。
