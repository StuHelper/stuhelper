# 通知中心

## 范围

保留统一站内通知，向用户解释与本人有关的业务结果。消息队列、连接协议和移动推送服务商在后续技术设计中确定。

## 已确认的通知与操作

| 来源 | 通知内容 |
| --- | --- |
| 内容互动 | 本人内容收到回复、点赞等互动 |
| 内容管理 | 内容处理结果、资料下架申请处理结果 |
| 举报 | 本人举报的处理结果 |
| 认证 | 学生认证或实名核验结果，学生认证撤销、删除申请处理结果 |
| 授课反馈 | 已认证教师所授课程新增公开评价的汇总通知 |
| 系统 | 与用户有关的系统通知 |

用户可查看通知列表与未读数，将单条通知标记已读，或将全部通知标记已读。点击通知可以进入相关内容、申请或结果页。通知对应内容已无法访问时，说明当前状态，不能只展示无法解释的空白页。

通知先进入站内。业务处理、安全与账号通知默认开启，互动通知可关闭并聚合。面向已认证教师提供独立的“所授课程新增公开评价汇总”可选开关，默认按日聚合，仅提示课程名称与新增公开评价数，不暴露匿名作者身份或未公开内容。邮件、QQ 与客户端推送由用户选择，免打扰延后外部推送，站内通知仍可查看。

保留期限、聚合窗口与提醒提前量由后台配置。QQ 群内提醒继续属于[群服务](qq-group-services.md)流程，额外通知渠道遵循用户选择。

导航铃铛、首页和消息中心共享未读数。并发读取复用同一请求，一分钟内复用已知结果。标记已读或清空后的状态优先于较早请求，读取失败保留已知值，未知值不显示数字。

通知列表通过 include_content_names=true 取得当前内容名称。可访问内容使用名称，失效或无权访问时显示不可用，依赖故障显示名称暂不可用。旧服务未返回增强字段时保留编号，内容名称不写入通知持久数据。

## 验收场景

| 场景 | 预期结果 |
| --- | --- |
| NT-01：用户收到回复通知 | 列表展示通知，点击进入对应内容 |
| NT-02：用户标记一条或全部已读 | 对应未读状态和未读数更新 |
| NT-03：申请已被管理员处理 | 用户能看到结果并进入相关申请 |
| NT-04：通知关联内容已下架 | 告知内容当前不可用，不误报加载成功但无内容 |
| NT-05：未登录或偏好输入无效 | 拒绝请求，不修改通知偏好 |
| NT-06：通知写入失败或达到保留边界 | 事务失败回滚，按保留期清理，聚合区分目标、参数与接收人 |
| NT-07：通知标题与参数 | 使用服务端封闭标题目录，拒绝无效标题与参数，互动计数来自聚合结果 |
| NT-08：重复事件与旧修订 | inbox 去重并返回原结果，旧修订不覆盖新状态，失败回滚聚合与修订 |
| NT-09：一个事件包含多个收件人 | 去重并逐人应用偏好，全部通知、inbox 与修订同事务写入，失败全部回滚 |
| NOTIFY-BELL-01：共享未读数与并发更新 | 页面共用当前数值，已读或清空后不被较早请求覆盖，失败保持有效状态 |
| NOTIFY-NAME-01：读取通知内容名称 | 使用当前可访问名称，隐藏或不可用时显示对应状态，旧响应保留编号 |
| NT-10：已认证教师订阅所授课程新评价汇总 | 开启后按日聚合推送课程新增公开评价数，关闭或待审撤回内容不发送，载荷不含匿名作者身份 |

## 配置与后续事项

通知业务规则已确认。具体渠道接入、发送能力与界面排版在实现阶段确定，未接入渠道不显示为已可使用。
