# 0002：按任务选择 CI runner

## 背景与设计条件

公共仓库使用 GitHub 托管 runner 完成普通检查。组织计费失败会拒绝启动私有仓库的托管作业，自建 ARC 作业仍可运行。项目 Registry 位于 BJ1，镜像构建与传输继续使用自建网络。

## 决策与确认依据

2026-11-15，负责人确认私有仓库的普通 push/PR 检查改用 stuhelper-arc 组、stuhelper-arc-sh-k8s 标签。公开仓库继续使用 GitHub ubuntu-26.04。公开 PR 不能接触能够读取私有源码、凭据或缓存的环境。

Docker/OCI 镜像构建与 BJ1 Registry 任务固定使用自建 runner。共享普通检查与附件发行通过调用方的 runs-on JSON 选择环境，公开调用方始终使用托管 runner。原生 iOS 编译仍需要 macOS，其他平台按实际 SDK 支持安排。

runner 镜像基于 Ubuntu 26.04 预装声明的工具版本。主机与容器系统分别维护，主机升级先核对实际发行版与可用备份，在无任务执行时操作。跨发行版重装须独立评估，不能直接执行 Ubuntu 原地升级命令。

私有依赖和构建缓存只保存在自建环境，按仓库和用途分区。可信 develop/main 成功后发布缓存，PR 只读。公开仓库不使用这些缓存。容量、保留期和清理按规格执行。版本使用明确 tag，摘要用于核验。

## 备选与取舍

按可见性分配普通检查，使私有仓库不再依赖托管作业的组织计费状态，并保持公开 PR 与内部资源隔离。代价是私有检查依赖自建容量与维护窗口，需要预装工具、缓存上限和可执行的回退方案。

## 后果与验证

迁移保留既有 check 名称，每个私有仓库在指定 ARC 上完成必需检查。验证公开 PR 仍使用托管环境，并以同一提交的首次与第二次运行衡量缓存效果。镜像、缓存与主机系统的实际结果分别记录。

完整规则见 [runner 规格](../spec/ci-runners.md)，当前可用操作见 [CI 指南](../guide/ci-runners.md)。
