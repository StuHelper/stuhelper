# 0004：按业务模块采用多仓库

## 背景

业务模块分别维护接口、数据和生命周期。学校数据接入、账务和生产配置还需要独立的仓库访问控制。

## 设计选择

项目负责人于 2026-10-24 确认按业务模块拆分仓库。模块拥有自己的数据、接口、版本和生命周期，通过公开契约协作。详细划分见[模块仓库设计](../design/module-repositories.md)。

认证与实名、学校适配、账务、QQ 绑定、正式后端装配及运维配置位于私有仓。公开的跨仓架构和对接规格由根仓维护。

私有 backend 装配公开与私有业务模块，运行时仍按模块隔离数据访问。官方 Casdoor 与 Koishi 的部署配置由 ops 维护。模块协作使用声明的接口。

## 影响

各模块独立检查和发行。跨仓联调记录实际依赖提交，生产晋级与迁移按 Ops 的版本组合验收。
